Supabase

Supabase przechowuje dane osobiste marcom-cadence: hostowana baza Postgres z logowaniem i automatycznym REST API (Data API). Przeglądarka rozmawia tylko z tym API i nigdy nie łączy się bezpośrednio z Postgresem. Podłączanie projektu krok po kroku opisuje dokument Konfiguracja Supabase.

Jak działa dostęp

Strona wysyła z każdym żądaniem dwie rzeczy:

  • Klucz publishable: publiczny, wskazuje projekt. Jest w js/supabase.js i w tym repozytorium. Sam nie daje dostępu do żadnych danych.
  • Token logowania (JWT): wydawany po zalogowaniu kontem aplikacji. Postgres wykonuje wtedy zapytanie jako rola authenticated, z identyfikatorem użytkownika z tokenu.

Każda tabela ma Row Level Security z polityką, która dopuszcza tylko wiersze, w których user_id jest równe zalogowanemu użytkownikowi. Pilnuje tego sama baza, więc znajomość klucza publishable nie wystarcza do odczytania czegokolwiek. Rola anon (niezalogowany) nie ma żadnych uprawnień do schematu aplikacji.

Nigdy nie trafiają do repozytorium ani do kodu strony:

  • klucz secret (dawniej service_role), który omija Row Level Security,
  • hasło do bazy, potrzebne tylko do bezpośredniego połączenia z narzędzia takiego jak pgAdmin czy psql,
  • tokeny dostępu konta (Access Tokens), które zarządzają całym kontem Supabase.

Panel Supabase (Table Editor, SQL Editor) działa jako rola postgres i widzi wszystkie dane. To on jest narzędziem administratora; aplikacja nie ma konta admina.

Opcje projektu:

  • Enable Data API: włączone, strona korzysta z tego API.
  • Automatically expose new tables: wyłączone. Każda tabela dostaje w swojej migracji jawne instrukcje grant dla roli authenticated.
  • Enable automatic RLS: włączone. Działa tylko na schemacie public, więc migracje włączają RLS jawnie na każdej tabeli.
  • Data API, Exposed schemas: zawiera marcom_cadence. Bez tego API odpowiada, że schemat nie jest udostępniony.

Logowanie

Aplikacja ma jedno konto, założone ręcznie. Ustawienia w sekcji Authentication:

  • Users: konto aplikacji, założone przez Add user, Create new user, z zaznaczonym Auto Confirm User.
  • Sign In / Providers: Allow new users to sign up jest wyłączone, więc nikt inny nie założy konta.
  • URL Configuration: Site URL to https://marcom-marekb.github.io/marcom-cadence/, a http://localhost:3100 jest w Redirect URLs.

Aplikacja loguje e-mailem i hasłem. supabase-js trzyma sesję w pamięci przeglądarki i odświeża token, więc formularz logowania pojawia się tylko po wylogowaniu albo po wygaśnięciu sesji.

Zmiany w bazie

Wszystkie tabele są w schemacie marcom_cadence. Zmiany schematu to pliki SQL w supabase/migrations/, nazwane <znacznik czasu>_<opis>.sql, tak jak nazywa je Supabase CLI.

Uruchamia je integracja Supabase z GitHubem: projekt jest połączony z repozytorium MARCOM-MarekB/marcom-cadence, z katalogiem roboczym . (folder, w którym leży supabase/) i gałęzią produkcyjną main. Działa na planie Free; osobne gałęzie bazy dla pull requestów wymagałyby planu Pro i nie są używane. Przy każdym pushu do main Supabase uruchamia pliki migracji, których jeszcze nie uruchomił, w kolejności nazw, i zapisuje je w supabase_migrations.schema_migrations. To odpowiednik dotnet ef database update w pipeline wdrożeniowym. Zastosowane migracje i przebiegi integracji widać w panelu.

Zastosowanego pliku nie zmienia się; późniejsza zmiana to nowy plik z późniejszym znacznikiem czasu.
