Konfiguracja Supabase

Konfiguracja krok po kroku, która łączy projekt Supabase z tym repozytorium i z aplikacją. Wszystko robi się klikając w panelu Supabase i na GitHubie, bez wiersza poleceń. Docelową konfigurację opisuje dokument Supabase.

Krok 1: użytkownik aplikacji

  1. Authentication, Users.
  2. Add user, Create new user.
  3. Wpisz e-mail i nowe hasło do logowania w Cadence.
  4. Zaznacz Auto Confirm User, żeby nie był wysyłany mail z potwierdzeniem.
  5. Create user.

Sprawdzenie: użytkownik pojawia się na liście z e-mailem i UID.

Krok 2: wyłączenie rejestracji

  1. Authentication, Sign In / Providers.
  2. Wyłącz Allow new users to sign up.
  3. Save changes.
  4. Provider Email zostaje włączony.

Od teraz nikt inny nie założy konta w aplikacji.

Krok 3: adresy

  1. Authentication, URL Configuration.
  2. Site URL: https://marcom-marekb.github.io/marcom-cadence/, potem Save changes.
  3. Redirect URLs: Add URL, http://localhost:3100, potem Save URLs.

Logowanie hasłem nie korzysta z tych adresów. Linki w mailach, np. reset hasła, przekierowują tylko na adresy z tej listy.

Krok 4: push kodu

Zrób commit i push repozytorium do main. Integracja z następnego kroku czyta pliki migracji z GitHuba, nie z Twojego dysku.

Krok 5: GitHub i migracje

  1. Project Settings, Integrations, GitHub, Connect.
  2. Autoryzuj Supabase na GitHubie i wybierz repozytorium marcom-cadence.
  3. Working directory: ., czyli folder, w którym leży supabase/, tutaj katalog główny repozytorium.
  4. Włącz Deploy to production.
  5. Production branch name: main.
  6. Automatic branching zostaje wyłączone; wymaga planu Pro.
  7. Zapisz.

Supabase uruchamia teraz każdy plik z supabase/migrations/, który jeszcze nie był uruchomiony. Jeśli nic się nie dzieje, wypchnij dowolny kolejny commit do main.

Krok 6: sprawdzenie bazy

  1. Table Editor.
  2. Przełącz schemat na liście w lewym górnym rogu na marcom_cadence.
  3. Jest tam tabela measurements.

Krok 7: udostępnienie schematu w Data API

  1. Project Settings, Data API.
  2. Dopisz marcom_cadence do Exposed schemas.
  3. Zapisz.

Lista schematów pokazuje tylko istniejące schematy, więc ten krok jest po migracji. Bez niego aplikacja pokazuje „Nie udało się wczytać pomiarów”.

Krok 8: test aplikacji

  1. Uruchom npm start w folderze repozytorium i otwórz http://localhost:3100.
  2. Zaloguj się użytkownikiem z kroku 1.
  3. Otwórz Pomiary i zapisz wartość.
  4. W Table Editor, schemat marcom_cadence, tabela measurements, pojawia się wiersz z Twoim UID w user_id.

Opublikowana strona https://marcom-marekb.github.io/marcom-cadence/ korzysta z tego samego projektu i tych samych danych.

Kolejne zmiany w bazie

Nowy plik w supabase/migrations/ wypchnięty do main integracja uruchamia sama. Kroków 1 do 7 się nie powtarza. Nowy schemat wymaga ponownie kroku 7.
